# Sidework

Sidework is an Astro server-rendered prototype with a public @mager profile and approval-only tools for developer profiles, personal software, upstream contributions, and opportunity discovery.

- Read README.md and DESIGN.md before UI work.
- Display people with @handles in headings, navigation, account details, and exports. Keep repository owner/name identifiers and URLs unchanged.
- Use real source evidence. Do not invent users, follower counts, stars, testimonials, merged states, or learning outcomes.
- Keep public profile snapshots separate from private account drafts and browser-local plans. Approved accounts save project stories, featured order, and contribution drafts in server-only `sidework_drafts`, keyed by verified GitHub numeric ID. Legacy sessions remain browser-local. Use GitHub numeric ID storage keys for account workspaces. Retain legacy browser data without automatic migration; theme stays browser-global.
- Account records use the server-only Firestore `sidework_accounts` collection, keyed by GitHub numeric ID. Use Vercel OIDC Workload Identity; do not create GCP service account keys. Keep browser Firestore access denied.
- Only the configured owner may start approved. Private exports, draft review, and MCP templates use the verified numeric account ID. Keep other accounts waiting until the release checks in docs/mvp.md pass. Waitlist signup does not publish a profile or send email.
- The separate admin deployment is owner-only and read-only. Recheck the configured GitHub numeric owner ID and current approval in Firestore on every private admin request. Use a separate admin session and a one-time PKCE handoff; main account cookies, legacy invite cookies, and agent tokens must not grant admin access. Keep approval, deletion, and email actions unavailable.
- Account draft GET/PUT requests require current approval and the expected account ID header; writes use revision checks and recheck approval in the Firestore transaction. Retain browser originals without automatic import. Browser import requires explicit review and gives saved account fields and order priority. Full account backup restore requires the same numeric ID and explicit review before replacing all private drafts and featured order. Settings reset changes browser data only. Profile draft exports are private backups, not publishing. Preserve authored fields and selected order when importing repositories.
- MCP tools may read committed records and public repositories or prepare drafts. They cannot read private account drafts, write drafts, or publish. Review links and files require an explicit browser save. Keep agent tokens separate from account and legacy invite cookies; never log them. API authentication lives in agent-auth.mjs and agent-http.mjs.
- Preserve explicit draft/merged/open/closed states and check dates.
- Do not introduce GitHub tokens into browser code. Public API refresh may fail; retain the snapshot.
- Use safe HTTP(S) URLs and text nodes for user or API data.
- Run `npm test` and `npm run build` for behavioral changes. Check both mobile and desktop for UI changes.
- Vercel deployment uses @astrojs/vercel. Main-site public application routes are /admin/connect/ (sign-in transfer only; no account list), /signup/, the exact /auth/github/ start and /auth/github/callback/ routes, the exact /mager/ profile, /invite/ (redirect only), and /api/signout. Waiting accounts may use /waiting/ and /api/account/updates but cannot enter the tools. Other application routes require an approved account session or a valid legacy invite cookie; /api/account/drafts requires an approved account and matching expected-account header; /api/mcp requires its own scoped bearer token. Recheck account approval for account tokens on each MCP request. On the separate admin deployment, only /admin/login/, /auth/admin/start/, /auth/admin/callback/, and /auth/admin/signout/ are public; / and /admin/ require the admin owner session, and other application routes are unavailable. Never bypass either gate for previews. Keep OAuth secrets, database credentials, invite hashes, and session secrets in server environment variables.
